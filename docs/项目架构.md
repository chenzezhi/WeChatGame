# 项目架构图

> 微信小游戏（cax 引擎）。本文件只描述**结构和调用关系**，不含玩法。
> 改代码前先看这里，能快速定位「要改的东西在哪个文件」。

---

## 一、总体分层

从上到下：越往下越通用，越往上越贴近具体业务。

```
┌───────────────────────────────────────────────┐
│  game.js                    入口：只做装配 + 启动  │
└───────────────────────────────────────────────┘
                    │ start(env)
                    ▼
┌───────────────────────────────────────────────┐
│  demo 层（场景）                              │
│  cocos-demo.js   sheet-demo.js   image-demo.js │
│  每个模块只导出 start(env)，负责「装什么、放哪」 │
└───────────────────────────────────────────────┘
                    │
                    ▼
┌───────────────────────────────────────────────┐
│  配置层（数据 → 对象）                        │
│  config/render.js   ← 模板 + 字段顺序（只写一次）│
│  table-mapper → string-mapper → mapper        │
│  表格字符串  ──逐层解析──▶  完整配置对象       │
└───────────────────────────────────────────────┘
                    │ 完整配置对象
                    ▼
┌───────────────────────────────────────────────┐
│  渲染层（配置对象 → cax 对象 → stage）        │
│  sprite-map   anim-map   image-map   (+ tile)  │
│  统一入口：render(stage, cfg)                 │
└───────────────────────────────────────────────┘
                    │
                    ▼
┌───────────────────────────────────────────────┐
│  引擎层（文件 → 图像 → 可取的帧）             │
│  asset-manager   cocos-atlas   atlas  texture  │
└───────────────────────────────────────────────┘
                    │
                    ▼
┌───────────────────────────────────────────────┐
│  libs/cax.js  →  stage（唯一的上屏画布）      │
└───────────────────────────────────────────────┘
```

## 二、文件职责清单

### 入口

| 文件 | 职责 |
|---|---|
| `game.js` | 只做装配：require cax → 建 Stage → 铺底色 → 依次启动 demo → 主循环。**不写游戏逻辑** |

### 配置 / 数据（只有数据，没有逻辑）

| 文件 | 职责 |
|---|---|
| `public/config/render.js` | **渲染配置模板**：每种渲染器的「完整默认值 + 字段顺序」，只写一次 |
| `public/config/assets.js` | 精灵图配置：大图路径 + 切法(layouts) + 动画段(clips) |
| `public/config/rules/atlas.js` | 图集数据协议：素材目录、图片扩展名、数据扩展名 |
| `public/config/rules/engines.js` | 引擎分工规则：动画用 `atlas.js`，静态用 `cocos-atlas.js` |

### 配置层（数据替换 / 解析）

| 文件 | 职责 | 依赖 |
|---|---|---|
| `mapper.js` | **对象 → 对象**：默认模板 + 深拷贝 + 深度合并，补全缺失字段 | 无 |
| `string-mapper.js` | **字符串 → 对象**：按字段顺序解析，`n` = 保持默认 | `mapper` |
| `table-mapper.js` | **表格 → 对象**：字段顺序可来自配置，表格里只写数据行 | `string-mapper` |

三层是**组合**关系，不是继承：表格 → 字符串 → 对象 → 完整配置。

### 渲染层（配置对象 → 舞台）

| 文件 | 职责 | 产出 | 依赖 |
|---|---|---|---|
| `sprite-map.js` | 图集小图 → 舞台，支持按名字 / 按序号 | `cax.Bitmap` × N | `tile` |
| `anim-map.js` | 精灵动画 → 舞台，支持平铺（影分身） | `cax.Sprite` × N | `atlas`, `tile` |
| `image-map.js` | 独立单图 → 舞台，平铺时**烘焙成 1 张大图** | `cax.Bitmap` | `texture`, `tile`, `cax` |
| `tile.js` | **纯计算**：区域 + 格子尺寸 + 间距 → 矩阵坐标 | 坐标数组 | 无 |

三个渲染器的统一入口都是 **`render(stage, cfg)`**：
配置里有平铺区域（`right`/`bottom` > 0）就平铺，没有就放一张。

### 引擎层（文件 → 图像）

| 文件 | 职责 | 依赖 |
|---|---|---|
| `asset-manager.js` | 按**名称**自动加载图集（`gameMap` → `gameMap.png` + `gameMap.json`），带缓存 | `cocos-atlas`, `rules/atlas` |
| `cocos-atlas.js` | Cocos 图集引擎：png + json → 「名字/序号 → 小图」，自动烘焙旋转帧 | `texture`, `cax` |
| `atlas.js` | 精灵图引擎：按 layouts 切格 + clips 组动画 → 循环播放的 Sprite | `texture`, `cax` |
| `texture.js` | **唯一**读图入口，同一 url 只读一次（缓存） | `cax` |

### 第三方

| 文件 | 说明 |
|---|---|
| `libs/cax.js` | 引擎。`require` 时会调 `wx.createCanvas()`，那一次就是唯一上屏画布 |

## 三、调用关系（game.js 实际启动顺序）

```
game.js
  │
  ├─1─ require('./libs/cax.js')            ← 创建上屏画布
  ├─2─ new cax.Stage()                     ← 舞台
  ├─3─ stage.add(new cax.Rect(...))        ← 底色矩形（最底层）
  │
  ├─4─ image-demo.start({stage})
  │      ├─ Render.image(stage)             ← 取默认模板 + 字段顺序
  │      ├─ table-mapper ─▶ string-mapper ─▶ mapper
  │      │      （表格行 → 完整配置对象数组）
  │      └─ image-map.render(stage, cfg)
  │           ├─ texture ─▶ cax             （读图）
  │           ├─ tile.grid()                （算平铺矩阵）
  │           └─ stage.add(烘焙好的大图)     （bottomLayer → 挪到最底）
  │
  ├─5─ cocos-demo.start({stage, onReady})
  │      ├─ asset-manager.atlas('gameMap')
  │      │    ├─ rules/atlas.js              （读协议：目录 / 扩展名）
  │      │    └─ cocos-atlas.create() ─▶ texture ─▶ cax
  │      ├─ Render.sprite(stage)
  │      ├─ table-mapper ─▶ string-mapper ─▶ mapper
  │      ├─ sprite-map.render(stage, cfg)    （按名字 / 序号取图挂舞台）
  │      └─ onReady()  ──────────────┐
  │                                   │
  ├─5b─ sheet-demo.start({stage}) ◀───┘      （等背景挂完再挂，保证在上层）
  │      ├─ anim-map.load(config/assets.js)
  │      │    └─ atlas.load() ─▶ texture ─▶ cax
  │      ├─ Render.anim(stage)
  │      ├─ table-mapper ─▶ string-mapper ─▶ mapper
  │      └─ anim-map.render(stage, cfg)
  │
  └─6─ startLoop(stage)                    ← requestAnimationFrame 循环 stage.update()
```

**为什么要 `onReady` 串起来**：cax 没有 `zIndex`，渲染顺序 = 添加顺序。两个 demo 都是异步读图，谁后加载完谁在上层，所以用回调确定顺序。

## 四、数据通道（重点）

三个渲染器**从同一个通道进**，只有最底下的渲染器不同。

```
                    统一数据通道
  ┌──────────────────────────────────────────────┐
  │  1. 默认模板 + 字段顺序（config/render.js）    │
  │     template: { url:'', x:0, y:0, scale:1, … } │
  │     fields  : 'url x y scale gap margin …'     │
  └──────────────────────────────────────────────┘
                        │
  ┌──────────────────────────────────────────────┐
  │  2. 数据行（只写差异，行尾可省略）             │
  │     'src/assets/mapBg/mb1.jpg n n 0.25'        │
  └──────────────────────────────────────────────┘
                        │
              table-mapper（字段顺序 + 数据行）
                        │
              string-mapper（按序解析，n = 跳过）
                        │
              mapper（深拷贝模板 + 深度合并）
                        │
                        ▼
  ┌──────────────────────────────────────────────┐
  │  3. 完整配置对象                              │
  │     { url, x:0, y:0, scale:0.25, gap:0, … }    │
  └──────────────────────────────────────────────┘
                        │
                        ▼
            renderer.render(stage, cfg)
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
   sprite-map       anim-map        image-map       ← 只有这一层不同
   （图集小图）      （精灵动画）      （独立单图）
        │               │               │
        ▼               ▼               ▼
    cax.Bitmap      cax.Sprite      cax.Bitmap
        └───────────────┴───────────────┘
                        ▼
                   stage.add()
```

### 字段顺序原则

**最常变的放前面，不常变的放后面**，这样行尾可以直接省略，不用写一串 `n`：

| 位置 | 字段 | 变得频率 |
|---|---|---|
| 1 | `name` / `url` | 每行都不同 |
| 2~3 | `x` `y` | 每行都不同 |
| 4 | `scale` / `height` | 常改 |
| 5~6 | `gap` `margin` | 偶尔改 |
| 7~8 | `right` `bottom` | 基本固定（通常=整屏） |

### 现状

| demo | 通道 | 写法 |
|---|---|---|
| `cocos-demo.js` | ✅ | `Render.sprite` → 表格 → `sm.render` |
| `image-demo.js` | ✅ | `Render.image` → 表格 → `ImageMap.render` |
| `sheet-demo.js` | ✅ | `Render.anim` → 表格 → `am.render` |

三个 demo 结构完全一致，只有「取哪个模板 + 调哪个渲染器」不同。

## 五、四类素材 → 引擎 → 渲染器

| 素材类型 | 例子 | 引擎 | 渲染器 | 能播动画 | 能平铺 |
|---|---|---|---|---|---|
| 独立单图 | `mapBg/mb1.jpg` | `texture` | `image-map` | ❌ | ✅ 烘焙 |
| Cocos 图集小图 | `gameMap` 里的 `hpBar` | `cocos-atlas`(+`asset-manager`) | `sprite-map` | ❌ | ✅ 复制 |
| 精灵图动画 | `roll.png` 的 `walk` | `atlas`(+`config/assets.js`) | `anim-map` | ✅ | ✅ 复制 |
| 纯色块 / 文字 | 底色矩形 | — | cax 原生 | ❌ | ❌ |

判断依据见 `public/config/rules/engines.js`：
**是不是精灵图（连续帧动画）** 才是分界线，跟「排得规不规整」无关。

## 六、平铺（tile）的统一约定

参数在三个渲染器里**完全一致**：

| 参数 | 含义 |
|---|---|
| `x, y` | 区域左上角 |
| `right, bottom` | 区域右下角（> 0 才平铺） |
| `scale` | 每个格子的倍数（`anim-map` 用 `height` = 目标高度） |
| `gap` | 格子间距 |
| `margin` | 区域四周留白 |

区别只在**落地方式**：

- `image-map`：**烘焙**——画进离屏画布，舞台上只挂 1 个对象
- `sprite-map` / `anim-map`：**复制**——舞台上真的创建 N 个对象
  （动画每帧在变，无法烘焙）

矩阵算法只有一份：`tile.js` 的 `Tile.grid()`。平铺语义是「铺满」，
区域除不尽时补一格，超出部分裁掉。

## 七、新增一个东西时，改哪里？

| 想做的事 | 改哪里 |
|---|---|
| 换背景图 | `image-demo.js` 数据行里的 url |
| 调背景平铺密度 / 间距 | `image-demo.js` 数据行里的 `scale` / `gap` |
| 加一个新动画 | `public/config/assets.js` 的 `clips` |
| 加一张 Cocos 图集 | 图片 + json 放进 `src/assets/`，`assets.atlas('名字')` |
| 改素材目录 / 扩展名 | `public/config/rules/atlas.js` |
| 改渲染默认值 / 字段顺序 | `public/config/render.js` |
| 调窗口 / 启动顺序 | `game.js` |
