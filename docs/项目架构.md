# 项目架构图

> 微信小游戏（cax 引擎）。本文件只描述**结构和调用关系**，不含玩法。
> 改代码前先看这里，能快速定位「要改的东西在哪个文件」。

---

## 一、总体分层

从上到下：越往下越通用，越往上越贴近具体业务。

```
┌───────────────────────────────────────────────┐
│  game.js                     入口：只做装配 + 启动 │
└───────────────────────────────────────────────┘
                    │ start(env)
                    ▼
┌───────────────────────────────────────────────┐
│  场景层   demo.js（只有一个）                  │
│  一张表格描述整个画面：谁用哪个渲染器、放哪、多大 │
└───────────────────────────────────────────────┘
                    │
                    ▼
┌───────────────────────────────────────────────┐
│  配置层（表格字符串 → 对象）                   │
│  config/render.js  ← 默认值模板（只写一次）     │
│  table-mapper → string-mapper → mapper        │
└───────────────────────────────────────────────┘
                    │ 完整配置对象
                    ▼
┌───────────────────────────────────────────────┐
│  渲染层（配置对象 → cax 对象 → stage）         │

                    ▼
```

## 二、文件职责清单

### 入口 / 场景

| 文件 | 职责 |
|---|---|
| `game.js` | 只做装配：require cax → 建 Stage → 铺底色 → 启动 demo → 主循环 |
| `public/core/demo.js` | **唯一**的场景文件：一张表格描述整个画面 |

### 配置 / 数据（只有数据，没有逻辑）

| 文件 | 职责 |
|---|---|
| `public/config/render.js` | 渲染配置的**默认值模板**（字段的默认值，只写一次） |
| `public/config/assets.js` | 精灵图配置：大图路径 + 切法(layouts) + 动画段(clips) |
| `public/config/rules/atlas.js` | 图集数据协议：素材目录、图片扩展名、数据扩展名 |
| `public/config/rules/engines.js` | 引擎分工规则：动画用 `atlas.js`，静态用 `cocos-atlas.js` |
| `public/config/board.js` | 棋盘布局：字符图 + 尺寸比例 + 格子图集序号 |

### 模型层（数据 → 表格行）

| 文件 | 职责 | 产出 | 依赖 |
|---|---|---|---|
| `public/core/board.js` | **棋盘**：布局字符串 → `Cell` 对象数组，算出坐标后生成表格行 | `Cell[]` + 字符串行 | 无 |

分层：`config/board.js`（纯数据）→ `board.js`（算坐标、生成行）→ `demo.js`（把行拼进表格）。
格子之间不互相调用，格子上的卡牌以后直接挂在 `cell.card` 上。

### 配置层（表格 / 字符串 → 对象）

| 文件 | 职责 | 依赖 |
|---|---|---|
| `table-mapper.js` | **表格 → 对象**：第 0 元素是字段头，其余是数据行 | `string-mapper` |
| `string-mapper.js` | **字符串 → 对象**：按字段顺序解析，`n` = 跳过 | `mapper` |
| `mapper.js` | **对象 → 对象**：深拷贝模板 + 深度合并，补全缺失字段 | 无 |

三层是**组合**关系：表格 → 字符串 → 对象 → 完整配置。

### 渲染层（配置对象 → 舞台）

| 文件 | 职责 | 产出 | 依赖 |
|---|---|---|---|
| `sprite-map.js` | 图集小图 → 舞台（按名字 / 按序号） | `cax.Bitmap` × N | `tile` |
| `anim-map.js` | 精灵动画 → 舞台（支持影分身） | `cax.Sprite` × N | `atlas`, `tile` |
| `image-map.js` | 独立单图 → 舞台（平铺时**烘焙成 1 张大图**） | `cax.Bitmap` | `texture`, `tile`, `cax` |
| `tile.js` | **纯计算**：区域 + 格子尺寸 + 间距 → 矩阵坐标 | 坐标数组 | 无 |

三个渲染器的统一入口都是 **`render(stage, cfg)`**：
配置里 `right`/`bottom` 大于 0 就平铺，否则只放一张。

### 引擎层（文件 → 图像）

| 文件 | 职责 | 依赖 |
|---|---|---|
| `asset-manager.js` | 按**名称**自动加载图集（`gameMap` → `gameMap.png` + `.json`） | `cocos-atlas`, `rules/atlas` |
| `cocos-atlas.js` | Cocos 图集引擎：png + json → 「名字/序号 → 小图」，自动烘焙旋转帧 | `texture`, `cax` |
| `atlas.js` | 精灵图引擎：layouts 切格 + clips 组动画 → 循环播放的 Sprite | `texture`, `cax` |
| `texture.js` | **唯一**读图入口，同一 url 只读一次（缓存） | `cax` |

### 第三方

| 文件 | 说明 |
|---|---|
| `libs/cax.js` | 引擎。`require` 时会调 `wx.createCanvas()`，那一次就是唯一上屏画布 |

## 三、调用关系

```
game.js
  │
  ├─1─ require('./libs/cax.js')            ← 创建上屏画布
  ├─2─ new cax.Stage()                     ← 舞台
  ├─3─ stage.add(new cax.Rect(...))        ← 底色矩形（最底层）
  │
  ├─4─ demo.start({stage})
  │      │
  │      ├─ 表格 → TableMapper.fill(TEMPLATE, table)
  │      │     └─ string-mapper → mapper     （逐行生成完整配置对象）
  │      │
  │      ├─ 准备资源（异步，全部等齐）
  │      │     ├─ SpriteMap.of(assets.atlas('gameMap')).ready()
  │      │     ├─ AnimMap.load(config/assets.js)
  │      │     └─ ImageMap.size(url)  × 表格里每个 image 行（预热）
  │      │
  │      └─ whenReady → 按表格顺序逐行渲染
  │            ├─ renderer=image  → ImageMap.render()
  │            │      ├─ texture ─▶ cax        （读图，已预热 → 同步）
  │            │      ├─ tile.grid()           （算平铺矩阵）
  │            │      └─ stage.add(烘焙的大图)
  │            ├─ renderer=sprite → SpriteMap.render()
  │            │      └─ stage.add(取到的小图)
  │            └─ renderer=anim   → AnimMap.render()
  │                   └─ stage.add(Sprite)
  │
  └─5─ startLoop(stage)                    ← requestAnimationFrame → stage.update()
```

**为什么要「先等齐资源」**：cax 没有 `zIndex`，渲染顺序 = 添加顺序。
先等所有图加载完，再按表格顺序同步渲染，层级就和表格顺序一致了。

## 四、数据通道（重点）

所有渲染走**同一条通道**，只有最后一层的渲染器不同。

```
  ┌──────────────────────────────────────────────┐
  │ 1. 表格（config/render.js 提供默认值模板）      │
  │                                                │
  │   renderer name x y scale gap margin right bottom │  ← 第 0 行：字段头
  │   image mb1.jpg 0 0 0.25 n n W H               │  ← 数据行
  │   sprite 30 100 200 0.5                        │
  │   anim walk 200 400 2                          │
  └──────────────────────────────────────────────┘
                        │
          table-mapper（第 0 行当字段头）
                        │
          string-mapper（按序解析，n = 跳过）
                        │
          mapper（深拷贝默认模板 + 深度合并）
                        │
                        ▼
  ┌──────────────────────────────────────────────┐
  │ 2. 完整配置对象                                │
  │    { renderer:'image', name:'mb1.jpg',         │
  │      x:0, y:0, scale:0.25, gap:0, … }          │
  └──────────────────────────────────────────────┘
                        │
                        ▼
            按 cfg.renderer 分发
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
   sprite-map       anim-map        image-map      ← 只有这一层不同
   （图集小图）      （精灵动画）      （独立单图）
        └───────────────┴───────────────┘
                        ▼
                   stage.add()
```

### 字段顺序原则

`renderer` **必须在第一个**（一眼看出这行用哪个渲染器），
其余按「最常变 → 不常变」排列，这样行尾可以直接省略，不用写一串 `n`：

| 位置 | 字段 | 变得频率 |
|---|---|---|
| 1 | `renderer` | 每行都要写 |
| 2 | `name` | 每行都不同 |
| 3~4 | `x` `y` | 每行都不同 |
| 5 | `scale` | 常改 |
| 6~7 | `gap` `margin` | 偶尔改 |
| 8~9 | `right` `bottom` | 基本固定（通常=整屏） |

## 五、四类素材 → 引擎 → 渲染器

| 素材类型 | 例子 | 引擎 | 渲染器 | 能播动画 | 能平铺 |
|---|---|---|---|---|---|
| 独立单图 | `mapBg/mb1.jpg` | `texture` | `image` | ❌ | ✅ 烘焙 |
| Cocos 图集小图 | `gameMap` 里的 `hpBar` | `cocos-atlas`(+`asset-manager`) | `sprite` | ❌ | ✅ 复制 |
| 精灵图动画 | `roll.png` 的 `walk` | `atlas`(+`config/assets.js`) | `anim` | ✅ | ✅ 复制 |
| 纯色块 / 文字 | 底色矩形 | — | cax 原生 | ❌ | ❌ |

判断依据见 `public/config/rules/engines.js`：
**是不是精灵图（连续帧动画）** 才是分界线，跟「排得规不规整」无关。

## 六、平铺（tile）的统一约定

三个渲染器参数**完全一致**：

| 参数 | 含义 |
|---|---|
| `x, y` | 区域左上角 |
| `right, bottom` | 区域右下角（> 0 才平铺） |
| `scale` | 每个格子的倍数（`anim` 也支持 `height` = 目标高度） |
| `gap` | 格子间距 |
| `margin` | 区域四周留白 |

区别只在**落地方式**：

- `image-map`：**烘焙**——画进离屏画布，舞台上只挂 1 个对象
- `sprite-map` / `anim-map`：**复制**——舞台上真的创建 N 个对象

矩阵算法只有一份：`tile.js` 的 `Tile.grid()`。平铺语义是「铺满」，
区域除不尽时补一格，超出部分裁掉。

## 七、新增一个东西时，改哪里？

| 想做的事 | 改哪里 |
|---|---|
| 加一张图 / 换个背景 | `demo.js` 表格里加一行 / 改 `name` |
| 改棋盘形状 / 加格子 | `public/config/board.js` 的 `map` |
| 改格子大小 / 间距 / 位置 | `public/config/board.js` 的 `cellRatio` / `gapRatio` / `topRatio` |
| 换格子用的图 | `public/config/board.js` 的 `cellSprite`（图集序号） |
| 换渲染器 | 改表格里的 `renderer` 字段 |
| 调平铺密度 / 间距 | 改表格里的 `scale` / `gap` |
| 加一个新动画 | `public/config/assets.js` 的 `clips` |
| 加一张 Cocos 图集 | 图片 + json 放进 `src/assets/`，`assets.atlas('名字')` |
| 改素材目录 / 扩展名 | `public/config/rules/atlas.js` |
| 改渲染默认值 | `public/config/render.js` |
| 调窗口 / 启动顺序 | `game.js` |

## 九、改动流程

1. 先确认要改的东西在哪个文件（见第七节）。
2. 读原文件再改，不凭记忆写。
3. 只改被要求的部分，不顺手重构别的模块。
4. 数值类改动优先落到 `public/config/`，不要把数字散进渲染代码。
5. 一次只做一个能跑起来的增量，改完先看看画面对不对。
